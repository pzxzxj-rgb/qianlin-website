# 测试与验证规范

## 1. 目标

确保 `qianlin-website` 的每次代码修改，都经过与风险相匹配的测试和验证。

测试不是为了让命令显示绿色，而是为了确认：

- 新功能按照预期运行
- 原有功能没有被意外破坏
- 不同旅行社的数据不会串租户
- 未登录用户不能访问管理后台
- 客户端不能伪造租户身份
- 输入校验不能被绕过
- 数据库 Migration 不会破坏已有数据
- 本地代码具备部署条件
- 测试不会访问或破坏生产数据
- 未测试内容和剩余风险被明确报告

代码写完不等于任务完成。

功能只有在相关验证完成后才算完成。

---

## 2. 当前项目技术与测试体系

当前项目主要使用：

- Next.js
- Vinext
- React
- TypeScript
- Cloudflare Workers
- Cloudflare D1
- Drizzle ORM
- ESLint
- Node.js Test Runner
- Wrangler 本地 D1
- 本地 HTTP 集成测试

当前项目主要验证命令：

```bash
npm run lint
npm run build
npm test
npm run test:integration:local
```

开始任务前必须先查看当前 `package.json`，确认脚本定义没有变化。

当前项目的 `npm test` 已经包含一次生产构建。

因此：

- 单独验证构建时可以运行 `npm run build`
- 运行完整 `npm test` 时，不需要为了报告格式再次重复执行 `npm run build`
- 如果已经先运行过 `npm run build`，之后仍可运行 `npm test`，但必须知道这会重复构建
- 报告中必须如实说明实际执行了哪些命令

不得因为 Skill 中写死了旧命令，而忽略 `package.json` 中已经发生的变化。

---

## 3. 测试工具规则

不得擅自引入新的测试框架。

只有当现有工具确实无法覆盖需求时，才可以提出新工具，并且必须先说明：

- 现有工具为什么无法覆盖
- 新工具解决什么问题
- 会增加哪些依赖
- 会修改哪些脚本
- 是否影响 Cloudflare 部署
- 是否影响构建速度
- 是否有更简单的替代方案
- 是否需要用户明确同意

不得仅因为熟悉某个测试框架就擅自替换当前测试体系。

## 5. 风险等级

开始修改前，必须判断本次任务风险。

### 5.1 低风险

通常包括：

- 纯文案修改
- 纯样式修改
- 静态图片替换
- README 修改
- 不影响行为的注释修改

低风险任务必须同时满足：

- 不改变表单字段
- 不改变交互行为
- 不改变 API
- 不改变数据库
- 不改变租户逻辑
- 不改变认证逻辑
- 不改变环境变量
- 不改变部署配置
- 不改变安全校验

### 5.2 中风险

通常包括：

- React 组件修改
- 页面交互修改
- 表单前端修改
- SEO 或 metadata 修改
- 数据转换逻辑修改
- 不写数据库的 API 修改
- 本地图片白名单修改
- 页面加载、错误或成功状态修改

### 5.3 高风险

通常包括：

- 数据库读取或写入
- D1 Migration
- 管理员认证
- Session 或 Cookie
- 租户数据
- 后台写操作
- 咨询提交
- 个人信息处理
- Origin 校验
- Turnstile
- 批量更新或删除
- 文件路径验证
- 权限系统
- 部署配置
- 环境变量
- 安全问题修复
- 跨租户访问

无法确定风险等级时，默认按更高风险处理。

## 6. 测试级别

### 6.1 静态检查

主要发现：

- 语法错误
- 未使用变量
- 错误导入
- 明显类型问题
- 不符合项目规范的代码
- 错误的 React 使用方式
- 明显的 Promise 或异步处理问题

命令：

```bash
npm run lint
```

### 6.2 构建检查

主要发现：

- TypeScript 编译错误
- Next.js 或 Vinext 构建错误
- Server Component 和 Client Component 边界错误
- 路由错误
- 文件导入错误
- 环境变量读取错误
- 仅在生产构建中出现的问题

命令：

```bash
npm run build
```

如果后续执行的 `npm test` 已包含 build，可以不重复单独执行，前提是报告中如实说明。

### 6.3 自动化测试

主要检查：

- 输入验证函数
- 数据转换逻辑
- 图片白名单
- 行程规划规则
- 租户查询约束
- 渲染后的 HTML
- SEO 和 metadata
- Turnstile 配置
- 源代码安全约束
- 回归问题

命令：

```bash
npm test
```

### 6.4 本地集成测试

主要检查：

- D1 Migration
- 数据库外键
- CHECK 约束
- 租户数据隔离
- 管理员登录
- Session Cookie
- 后台写操作
- API 请求
- 咨询提交
- 跨租户攻击
- 完整 HTTP 请求流程

命令：

```bash
npm run test:integration:local
```

本地集成测试必须：

- 使用项目自己的本地 D1 状态目录
- 不连接远程 D1
- 不使用生产数据
- 不覆盖日常开发数据库
- 在完成后清理临时测试状态

## 7. 不同修改类型的最低要求

### 7.1 纯文案或纯样式修改

最低要求：

- 检查修改范围
- 运行 `npm run lint`
- 完成必要的页面人工检查

如果修改影响以下内容，还必须执行相关构建或测试：

- HTML 结构
- 页面标题
- SEO 内容
- Meta 信息
- 表单标签
- 无障碍属性
- 响应式结构
- 条件渲染内容
- 页面快照或渲染测试

纯文案或纯 CSS 修改通常不需要运行本地 D1 集成测试。

### 7.2 React 组件或页面修改

最低要求：

- `npm run lint`
- 执行包含构建的验证命令
- `npm test`
- 人工检查受影响页面

还必须检查：

- 页面正常渲染
- 没有明显 hydration 问题
- Server 和 Client Component 边界正确
- 按钮正常点击
- 表单正常输入
- 加载状态完整
- 成功状态完整
- 失败状态完整
- 手机端布局没有明显破坏
- 键盘操作基本可用
- 页面没有显示其他租户数据

### 7.3 API 或业务逻辑修改

最低要求：

- `npm run lint`
- `npm test`
- 针对新逻辑增加成功与失败测试

涉及以下内容时，还必须运行：

```bash
npm run test:integration:local
```

触发条件：

- 数据库读取
- 数据库写入
- Session
- Cookie
- 管理员后台
- 咨询提交
- 租户数据
- Origin 校验
- Turnstile
- 文件或图片路径验证
- 跨租户访问
- 批量操作

### 7.4 数据库 Schema 或 Migration 修改

必须执行：

- 静态检查
- 包含生产构建的验证
- 自动化测试
- 本地 D1 集成测试

必须验证：

- 全新数据库可以从零执行全部 Migration
- 已有数据库可以增量执行最新 Migration
- 外键检查通过
- 不存在孤立记录
- 租户表的 `tenant_id` 不为空
- 正式租户数据保持正确
- 演示租户数据保持正确
- 唯一约束符合租户内唯一规则
- 索引符合真实查询
- 旧数据升级后仍可使用
- 没有连接远程 D1

必须执行或等效验证：

```sql
PRAGMA foreign_key_check;
```

正常结果应为空。

### 7.5 管理员认证或 Session 修改

必须执行全部相关测试。

至少测试：

- 正确用户名和密码
- 错误用户名
- 错误密码
- 空用户名
- 空密码
- 缺少管理员环境变量
- 未登录访问后台页面
- 未登录调用后台 API
- Session Cookie 被篡改
- Session 已过期
- Session 租户错误
- Cookie 包含 HttpOnly
- Cookie 包含正确 SameSite
- 生产环境使用 Secure
- 退出登录后 Cookie 被清除
- 登录错误不泄露用户名是否存在
- 响应不返回密码
- 响应不返回 Token
- 响应不返回完整 Session
- 错误 Origin 被拒绝
- 请求体过大被拒绝
- 非 JSON 请求被拒绝

### 7.6 多租户功能修改

任何涉及租户数据的任务，必须同时遵守：

- `tenant-isolation`
- `testing-validation`

必须包含真实跨租户失败测试。

不能只测试正常成功路径。

## 8. 多租户强制测试矩阵

任何涉及租户数据的功能，至少测试：

1. `qianlin-travel` 可以读取自己的数据。
2. `qianlin-travel` 可以在权限允许时修改自己的数据。
3. `qianlin-travel` 不能读取 `yunnan-demo` 的私有数据。
4. `qianlin-travel` 不能修改 `yunnan-demo` 的数据。
5. `qianlin-travel` 不能删除 `yunnan-demo` 的数据。
6. 请求体伪造 `tenantId` 必须失败。
7. 请求体伪造 `tenant_id` 必须失败。
8. 请求体伪造 `tenantSlug` 必须失败。
9. 伪造其他租户资源 ID 必须失败。
10. 伪造其他租户 Session 必须失败。
11. 过期 Session 必须失败。
12. 被篡改的 Session 必须失败。
13. 批量操作混入其他租户资源必须失败。
14. Tenant A 操作后 Tenant B 数据保持不变。
15. 错误响应不得透露 Tenant B 资源是否存在。
16. 日志不得输出 Tenant B 敏感数据。
17. 删除操作不能跨租户级联删除数据。
18. 资源自身 slug 只能在当前租户范围内生效。

跨租户失败测试属于强制测试，不得省略。

详细租户规则以 `tenant-isolation` Skill 为准。

## 9. API 测试要求

新增或修改 API 时，应根据风险覆盖以下内容。

### 9.1 请求方法与格式

测试：

- 正确 HTTP 方法
- 不支持的 HTTP 方法
- 缺少请求体
- 空请求体
- 非 JSON 请求
- JSON 格式错误
- 请求体超过大小限制
- 缺少 Content-Type
- 错误 Content-Type

### 9.2 输入字段

测试：

- 必填字段缺失
- 字段类型错误
- 空字符串
- 只有空格
- 超出最大长度
- 未知字段
- 危险字段
- HTML 内容
- Script 内容
- 非法 URL
- 非法枚举值
- 非法图片路径
- 路径穿越内容
- 外部图片地址
- `data:` 地址
- `blob:` 地址
- 不允许的协议
- 重复字段或冲突字段

资源自身的 `slug` 可以是合法字段，但必须验证：

- 格式
- 长度
- 当前租户内唯一性
- 不用于决定租户身份

### 9.3 身份与来源

测试：

- 未登录
- Session 无效
- Session 过期
- Session 被篡改
- Session 租户错误
- Origin 不合法
- 租户不匹配
- 权限不足
- 请求伪造租户字段
- 请求伪造资源归属字段

### 9.4 响应结果

检查：

- 成功状态码正确
- 失败状态码正确
- `Cache-Control` 符合要求
- 错误信息不泄露内部实现
- 错误信息不泄露其他租户资源
- 响应不包含密码
- 响应不包含 Token
- 响应不包含 Session
- 响应不包含不应公开的租户字段
- 写入成功后数据库内容正确
- 写入失败后没有部分修改
- 重复请求行为符合设计
- 数据库状态与返回结果一致

## 10. 表单测试要求

新增或修改表单时必须检查：

- 初始值正确
- 必填项提示正确
- 字数限制正确
- 字段类型限制正确
- 未知字段被服务端拒绝
- 提交中按钮不可重复点击
- 成功提示正确
- 失败提示正确
- 网络异常提示正确
- Session 失效提示正确
- 服务端执行最终验证
- 客户端验证不能替代服务端验证
- 重复提交不会意外创建多条数据
- 取消按钮不会意外保存
- 页面刷新后显示数据库最新内容
- 键盘操作基本可用
- 表单标签和输入框正确关联

涉及个人信息时还必须检查：

- 隐私同意是否必填
- 日志是否输出个人信息
- 测试数据是否为虚构数据
- 错误响应是否返回完整个人信息
- 页面是否意外展示其他咨询人的信息
- 测试输出是否包含真实手机号、邮箱或微信号

---

## 11. 数据库测试要求

数据库相关测试必须检查：

- 表是否存在
- 字段类型是否正确
- 非空约束是否正确
- 默认值是否合理
- 外键是否有效
- 删除策略是否正确
- 唯一约束是否正确
- 租户内唯一是否包含 `tenant_id`
- 联合索引是否匹配实际查询
- CHECK 约束是否生效
- Migration 顺序是否正确
- 全新安装路径可以运行
- 已有数据库升级路径可以运行
- 不存在孤立数据
- 不存在空租户 ID
- 不存在错误默认租户
- Tenant A 与 Tenant B 数据互不覆盖

不得为了让测试通过而关闭外键检查。

---

## 12. 安全回归测试

以下问题修复后必须添加安全回归测试：

- 跨租户漏洞
- 身份认证绕过
- Session 伪造
- Session 过期未失效
- 非法 Origin 请求
- XSS 或危险输入
- 非法图片路径
- 路径穿越
- 敏感数据泄露
- Migration 数据损坏
- 未登录访问后台
- 未授权修改数据
- 请求体伪造租户字段
- 请求体过大
- 未知字段绕过
- 批量操作越权
- 资源 slug 引发租户边界错误

安全问题修复后，必须保留能够重现旧问题的测试。

不能只修复代码而不留下测试。

---

## 13. 禁止行为

严禁通过以下方式让测试通过：

- 删除失败测试
- 注释失败测试
- 使用 `.skip`
- 使用 `.only`
- 降低断言严格程度
- 把具体断言改成只检查有返回值
- 删除失败状态码检查
- 删除跨租户测试
- 删除认证失败测试
- 用 Mock 完全代替关键数据库测试
- 捕获异常但不让测试失败
- 修改测试数据掩盖业务错误
- 因测试耗时默认跳过集成测试
- 未运行测试却声称通过
- 只运行单个测试却声称全部通过
- 把真实错误改成已知警告后忽略
- 为通过测试放宽安全校验
- 为通过测试允许未知字段
- 为通过测试信任客户端租户字段
- 连接生产数据库进行测试
- 使用真实客户数据作为测试数据

如果测试本身确实错误，必须先说明：

- 测试为什么错误
- 原规则为什么不再适用
- 新的预期行为是什么
- 修改测试是否存在安全影响
- 是否需要更新项目文档

---

## 14. 不得自动执行的操作

未经用户明确授权，不得：

- 执行远程 D1 Migration
- 清空远程数据库
- 修改生产数据
- 使用真实客户咨询作为测试数据
- 把 `.env.local` 提交到 GitHub
- 把 `.dev.vars` 提交到 GitHub
- 在测试日志中输出管理员密码
- 把生产密钥写进测试文件
- 修改真实域名配置
- 修改生产 Turnstile 密钥
- 连接生产数据库执行测试
- 把生产数据复制到测试数据库
- 删除生产 Migration 记录
- 修改远程 Cloudflare 资源
- 进行真实部署

本地集成测试必须使用独立的本地 D1 状态目录。

## 15. 测试失败处理流程

测试失败时必须：

1. 记录失败命令。
2. 找到第一个有意义的错误。
3. 判断属于代码错误、测试错误还是环境错误。
4. 修复根本原因。
5. 重新运行直接失败的测试。
6. 修复后重新运行相关完整测试。
7. 确认没有新增其他失败。
8. 报告仍未解决的问题。
9. 报告是否存在环境限制。
10. 不得掩盖失败结果。

不得在多个错误之间盲目修改代码。

不得只运行最后失败的测试文件，就宣称整个项目通过。

## 18. 功能完成标准

功能只有同时满足以下条件才算完成：

- 代码已经保存
- 静态检查通过
- 包含生产构建的验证通过
- 相关自动化测试通过
- 必要的本地集成测试通过
- 跨租户测试通过
- 没有测试被跳过
- 没有连接远程数据库
- 没有提交真实密钥
- 没有使用真实客户数据
- 已明确报告未测试内容
- 已明确报告剩余风险
- 已完成必要人工检查

代码已经写完，不等于任务已经完成。

## 20. 低风险例外

纯文案或纯 CSS 修改可以不运行本地 D1 集成测试，但必须同时满足：

- 不改变表单字段
- 不改变交互行为
- 不改变 API
- 不改变租户逻辑
- 不改变认证逻辑
- 不改变数据库
- 不改变环境变量
- 不改变部署配置
- 不改变安全校验
- 不改变条件渲染
- 不改变 SEO 或 metadata 生成逻辑

使用低风险例外时，必须在完成报告中说明原因。

无法确定是否属于低风险时，默认按照较高风险处理。

## 21. 与其他 Skill 的配合

涉及租户数据时，必须同时遵守：

- `tenant-isolation`
- `testing-validation`

先满足租户隔离规则，再设计测试。

当仓库中已经存在对应 Skill 时：

- 部署任务同时遵守 `deployment-operations`
- 用户和权限任务同时遵守 `auth-org-rbac`

如果对应 Skill 尚不存在，不得假装已经读取，也不得自行编造具体规则。

测试规则不能覆盖或降低安全规则。

## 22. 规则优先级

发生冲突时，按照以下顺序处理：

1. 租户隔离与数据安全
2. 数据完整性
3. 认证与授权
4. 个人信息保护
5. 生产环境安全
6. 测试真实性
7. 架构一致性
8. 开发便利性
9. 执行速度
